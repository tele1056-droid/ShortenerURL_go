# Инкремент 2. Тесты и DI

## Нужно покрыть юнит-тестами два хендлера (на этом этапе):
1. ShortenHandler — POST /
2. RedirectHandler — GET /{id}

Цель: защитить API от случайных изменений. Если кто-то (или вы сами) случайно сломает логику — тесты сразу покажут.

## Что будет происходить:
1. Мок-хранилище. Мы создаём storage.NewMemoryStorage() и передаём его в NewHandler. Это позволяет тестировать хендлер без реального сервера.
2. Фейковый запрос. httptest.NewRequest создаёт запрос с нужным методом, путём и телом.
3. Фейковый ответ. httptest.NewRecorder записывает всё, что хендлер пишет в w.
4. Вызов хендлера. Мы вызываем h.ShortenHandler(w, req) напрямую, как обычную функцию.
5. Проверки. Сравниваем код ответа и заголовок Location с ожидаемыми.

Запуск теста, можно перейти в папку с файлом теста, например handlers_test.go, и запустить через команду got test, либо с флагом go test -v (с подробным выводом)
И если PASS - то тесты прошли

## Запуск автотеста (от курса):
Изначально запускал этой командой: ./shortenertest.exe -test.v -test.run=^TestIteration2$ -binary-path=cmd/shortener/shortener.exe, но с этой командой автотест падал с ошибкой "-source-path non-empty flag required" - Это значит, что автотесту не хватает ещё одного флага — -source-path. н указывает, где лежат ваши исходники, чтобы тест мог их проанализировать (например, проверить наличие интерфейсов или структуру проекта).
Для исправления нужно добавить флаг -source-path=.  (точка означает «текущая папка», то есть корень проекта):
./shortenertest.exe -test.v -test.run=^TestIteration2$ -binary-path=cmd/shortener/shortener.exe -source-path=.
