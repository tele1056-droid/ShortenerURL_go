# Инкремент 3. Рефакторинг с помощью сторонней библиотеки (chi)

## Что сделано
- Заменён стандартный маршрутизатор `http.ServeMux` на сторонний роутер `github.com/go-chi/chi/v5`.
- Удалён ручной `mainHandler`, который проверял методы и пути. Теперь маршрутизацией занимается `chi`.
- Настроены явные маршруты:
  - `r.Post("/", h.ShortenHandler)` — для сокращения URL.
  - `r.Get("/{id}", h.RedirectHandler)` — для редиректа.
- Обновлён `RedirectHandler`: вместо ручного обрезания пути (`r.URL.Path[1:]`) используется `chi.URLParam(r, "id")`.
- Обновлены тесты для `RedirectHandler`: теперь запрос прогоняется через `chi.NewRouter()`, чтобы параметр `{id}` корректно извлекался.

## Зачем
- **Стандартизация:** `chi` — популярный и легковесный роутер, полностью совместимый с `net/http`.
- **Читаемость:** Явное указание методов (`r.Post`, `r.Get`) делает код понятнее, чем ручные проверки `if r.Method == ...`.
- **Гибкость:** `chi` упрощает добавление middleware (логирование, восстановление после паник), если это понадобится в будущем.
- **Безопасность:** Использование проверенной библиотеки снижает риск ошибок в ручной маршрутизации.

## Проблемы и решения
- **Проблема:** Тесты для `RedirectHandler` падали, потому что `chi.URLParam` возвращал пустую строку при прямом вызове хендлера (без роутера).
- **Решение:** В тестах создаётся `chi.NewRouter()`, регистрируется маршрут, и запрос прогоняется через `r.ServeHTTP(w, req)`. Это имитирует реальный путь запроса.

Так как используем стороннюю библиотеку chi, её нужно установить:
go get github.com/go-chi/chi/v5 
(вводим команду для установки из корня проекта (там, где лежит go.mod), это важно, т.к.go get добавляет зависимость именно в тот модуль, который указан в go.mod)
