# Инкремент 8. Поддержка gzip

## Что сделано
- Создан `middleware.DecompressMiddleware` для разжатия тела входящего запроса:
  - Проверяет заголовок `Content-Encoding: gzip`.
  - Если запрос сжат, создает `gzip.Reader` и подменяет `r.Body` на распакованное тело.
  - Удаляет заголовок `Content-Encoding` и устанавливает `Content-Type: text/plain`, чтобы хендлеры могли корректно обработать запрос.
- Создан `middleware.GzipMiddleware` для сжатия тела ответа:
  - Проверяет заголовок `Accept-Encoding` на наличие `gzip`.
  - Оборачивает `http.ResponseWriter` в кастомную структуру `gzipResponseWriter`, которая пропускает данные через `gzip.Writer`.
  - Устанавливает заголовок `Content-Encoding: gzip` и удаляет `Content-Length` (так как длина меняется после сжатия).
- Оба middleware подключены в `main.go` через `r.Use(...)` в правильном порядке:
  1. `DecompressMiddleware` (разжать запрос).
  2. `LoggerMiddleware` (залогировать).
  3. `GzipMiddleware` (сжать ответ).

## Зачем
- **Экономия трафика:** Сжатие уменьшает размер передаваемых данных, что особенно важно для API.
- **Стандарт:** Поддержка gzip — общепринятая практика для веб-сервисов.
- **Middleware:** Позволяет вынести сквозную логику из хендлеров, сохраняя их чистыми.

## Проблемы и решения
- **Проблема:** Автотест присылал запрос с `Content-Encoding: gzip` и `Content-Type: application/x-gzip`. `ShortenHandler` ожидал `text/plain` и возвращал `415 Unsupported Media Type`.
- **Решение:** В `DecompressMiddleware` после распаковки тела добавлена строка `r.Header.Set("Content-Type", "text/plain")`. Это позволило хендлеру корректно обработать запрос.
- **Проблема:** Автотест падал, потому что запускался старый бинарник (без изменений).
- **Решение:** Перед запуском автотестов всегда выполнять `go build -o cmd/shortener/shortener.exe ./cmd/shortener`.
