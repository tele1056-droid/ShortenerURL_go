# Инкремент 10. Подключение к PostgreSQL и хендлер /ping

## Что сделано
- В конфигурацию (`config.Config`) добавлено поле `DatabaseDSN`.
- Добавлена поддержка флага `-d` и переменной окружения `DATABASE_DSN` для передачи строки подключения к БД.
- В `main.go` реализовано подключение к PostgreSQL через пул соединений `pgxpool`:
  - Пул создается только если `DatabaseDSN` не пустой.
  - При создании выполняется проверка соединения (`pool.Ping`).
  - При успехе в лог пишется сообщение «подключение к БД установлено».
- В `handlers.Handler` добавлено поле `pool *pgxpool.Pool`.
- Создан хендлер `PingHandler` для эндпоинта `GET /ping`:
  - Если пул равен `nil` (БД не подключена) или `Ping` возвращает ошибку, возвращается `500 Internal Server Error`.
  - При успешной проверке возвращается `200 OK`.
- Зарегистрирован маршрут `r.Get("/ping", h.PingHandler)` в `main.go`.

## Зачем
- **Готовность к БД:** Это первый шаг к хранению данных в PostgreSQL (в следующих инкрементах).
- **Мониторинг:** Хендлер `/ping` позволяет быстро проверить, что сервис жив и имеет доступ к базе данных.
- **Гибкость:** Строка подключения задается через флаг или переменную окружения, что соответствует стандартам конфигурации.

## Проблемы и решения
- **Проблема:** При запуске автотеста без указания DSN сервер должен продолжать работать (использовать файловое хранилище).
- **Решение:** Подключение к БД выполняется только если `DatabaseDSN` не пустой. В противном случае `pool` остается `nil`, а хендлер `/ping` возвращает `500`.

## Результат
- Все автотесты для инкремента 10 пройдены.
- Сервер успешно подключается к PostgreSQL и отвечает на `/ping` кодом `200`.
