# Инкремент 9. Сохранение данных на диск и привязка URL к пользователю

## Что сделано
- **Формат файла:** Изменён на JSON Lines. Каждая строка — отдельный JSON-объект с полями:
  - `uuid` — уникальный идентификатор записи.
  - `short_url` — короткий код.
  - `original_url` — оригинальный URL.
  - `user_id` — идентификатор пользователя, создавшего ссылку.
- **Хранилище:** `FileStorage` и `MemoryStorage` обновлены:
  - Теперь хранят не просто строки, а структуры `URLRecord` (с `user_id`).
  - Добавлен метод `GetAllByUser(userID)`, который возвращает только URL конкретного пользователя.
- **Авторизация:** Реализована через куки:
  - При создании короткой ссылки (в `ShortenHandler` и `JSONShortenHandler`) генерируется `user_id` (UUID), если его нет, и устанавливается в куку.
  - При запросе `GET /api/user/urls` `user_id` читается из куки. Если куки нет — возвращается `204 No Content`.
- **Конфигурация:** Добавлен флаг `-f` и переменная окружения `FILE_STORAGE_PATH` (по умолчанию `/tmp/short-url-db.json`).

## Зачем
- **Персистентность:** Данные не теряются при перезапуске сервера.
- **Изоляция данных:** Каждый пользователь видит только свои ссылки. Это соответствует современным стандартам безопасности.
- **Читаемый формат:** JSON Lines удобен для ручного просмотра и отладки.

## Проблемы и решения
- **Проблема:** Автотест `fetch_no_urls` ожидал `204`, но сервер возвращал `200` со всеми URL, потому что не было привязки к пользователю.
- **Решение:** Внедрена авторизация через куки `user_id`. Теперь `GET /api/user/urls` возвращает только URL текущего пользователя.
- **Проблема:** Счётчик кодов не восстанавливался после перезапуска, что приводило к дубликатам `short_url` в файле.
- **Решение:** При загрузке файла (`load()`) счётчик обновляется до максимального `uuid`. В `main.go` вызывается `shortener.SetCounter(fs.GetMaxUUID())` для синхронизации.

## Результат
- Все автотесты для инкремента 9 пройдены.
- Костыль (проверка на отсутствие куки) удалён. Логика полностью соответствует требованиям.
