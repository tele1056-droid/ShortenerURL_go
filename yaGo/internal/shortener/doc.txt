В директории (пакете) shortener будет располагаться логика сокращения URL и храниения мапы (в которой будет храниться [string]string [шифр.URL]URl)
И в этом же пакете будут тесты к shortener.go, это удобно, все в одной директории (папке) и можно нормально протестировать

            == ЛОГИКА ==
Создаем для длинного URL короткий код (например, EwHXdJfB), который указывает на длинный исходный URL.
    Cхема:
Длинный URL: https://example.com/очень/длинный/путь?с=параметрами
       ↓ (вы генерируете код)
Короткий код: EwHXdJfB
       ↓ (сохраняете в память)
Карта: "EwHXdJfB" → "https://example.com/очень/длинный/путь?с=параметрами"

    Способы генерации кода:
1. Хэш от URL (детерминированный) + проверка на коллизии
2. Base62-кодирование (промышленный стандарт)
    Попробуем использовать Base62-кодирование


            == СУТЬ ЗАДАЧИ ==
Тут для длиного URL создаем короткий "псевдоним", т.е. генерируем код и сохраняем пока в памяти (в map).

То есть мы получаем запрос -> у нас будет счетчик на каждый запрос -> и именно это значение счетчика будем переводить в Base62 -> и это код будет ключем к URL, который передали через POST запрос

    *Попробуем генерировать через Base62, но возможно под тесты придется применять через составлнеие случайной строки из дилной 8 символов
