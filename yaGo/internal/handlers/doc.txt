В директории (пакете) handlers будут располагаться обработчки (хендлеры), для данного проекта достаточно будет одного .go файла для всех хендлеров (для небольших проектов 1-5 хендлеров), которые будут вызываться через маршрутизатор mux := http.NewServeMux() из cmd/main.go

Во втором инкременте-2:

Это подготовка: Внедряем интерфейс через DI (внедрение зависимостей), т.к. в начальной версии handlers жёстко привязан к конкретному хранилищу через пакет shortener (вызываются shortener.Shorten() и shortener.Get()). Это мешает тестированию и замене хранилища, поэтому внедряем DI.

Новая структура:
internal/
├── handlers/
│   └── handlers.go          // использует интерфейс Repository
├── storage/
│   ├── storage.go           // интерфейс Repository
│   └── memory.go            // реализация в памяти
└── shortener/
    └── shortener.go         // только toBase62 (генерация кода)

*Далее комментарии по инкрементам будут располагаться в папке docs/ в файлах с расширением .md (это расширение для Markdown. Markdown — это простой язык разметки текста, который легко читается и человеком, и компьютером.), docs/iter1 (как пример)
Примерно так:
my-project/
├── docs/
│   ├── iter1.md          // заметки по инкременту 1
│   ├── iter2.md          // заметки по инкременту 2
│   ├── iter3.md          // заметки по инкременту 3
│   └── README.md         // общее описание проекта
├── cmd/
├── internal/
└── go.mod

Как пример что и как писать в заметках (файлы .md):
docs/iter1.md:
# Инкремент 1. Базовый сервер

## Что сделано
- Создан HTTP-сервер на порту 8080.
- Реализован POST `/` для сокращения URL.
- Реализован GET `/{id}` для редиректа.
- Хранилище — map в памяти.

## Зачем
- Понять базовую работу с `net/http`.
- Научиться читать тело запроса и возвращать ответ.

## Проблемы и решения
- Гонка данных при параллельных запросах → добавил `sync.Mutex`.
- Невалидные URL → добавил проверки.

Что и как делать:
1. То есть на каждом инкременте создаем ветку под этот инкремент и переходим на неё
2. Потом создаем файл .md (для каждого инкремента по названию ветки) в docs/. В вс коде просто docs/ → New File → iter1.md
3. Пишем заметки и сохраняем
4. Далее коммитим (когда файл готов):
git add docs/iter1.md
git commit -m "docs: заметки по инкременту 1"
Или можно закоммитить всё вместе с выполненым инкрементом через git add ., git commit -m "iter1: базовый сервер + заметки"
и по итогу пушим, то есть при пуше отправляем на GitHub (git push)
